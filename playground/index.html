What is this, actually?

A messaging app already gives Android a “reply inline” button on most notifications. WristReply borrows that exact mechanism — it never reads your screen, never injects keystrokes and never opens the chat — and simply supplies better text for the button that is already there.

What it is

A headless Kotlin NotificationListenerService plus a Flutter cockpit for settings. The service watches the notification stream, decides whether a message deserves an answer, and publishes a silent companion notification carrying up to five tappable reply pills.

  • Runs without Flutter in memory (15–25 MB, 0% idle CPU)
  • Ships as a standalone .aar via EngineBootstrap
  • Discoverable at runtime — no hardcoded package list

How it works

Eight deterministic stages, each one cheap enough to run in the notification callback: gate → shield → token scan → debounce → ML Kit → multilingual fallback → context → publish. ML Kit runs first; if it returns nothing (non-English, unsupported device) the fallback banks take over.

  • Google ML Kit Smart Reply, created per call and closed in finally
  • 2.5 s hard timeout so a stalled model never blocks the shade
  • LRU cache collapses message bursts into one prompt

Why it is built this way

Because a smartwatch reply has to be instant and private. A round trip to a server costs 300–900 ms and puts your conversation on somebody else's disk. On-device inference costs milliseconds and nothing leaves the handset — the app does not even declare android.permission.INTERNET.

  • Play Data Safety: no data collected, no data shared
  • Works in airplane mode, in a metro, abroad
  • No account, no API key, no subscription

The eight-stage pipeline

Every stage maps to a real class in the repository. Run a message in the playground above and the strip lights up in the same order.

  1. 01 · Notification gateinspector/NotificationGate.kt

    Drops ongoing events, group summaries, our own companion notifications and blank payloads before any NLP compute is allocated.

  2. 02 · LPTE profanity shieldfilters/ProfanityGuardEngine.kt

    68 default multi-lingual tokens plus your own blocklist. An abusive message never receives a cheerful auto-reply.

  3. 03 · Token extractorfilters/SmartTokenExtractor.kt

    Pulls OTP codes and transaction IDs (Stripe, PayPal, UPI, Pix, iDEAL, bKash, bank SMS) and adds a one-tap copy action.

  4. 04 · Burst debounceguard/MessageDebounceBuffer.kt

    Rapid-fire messages from one sender collapse into a single 1.5 s window, so you get one prompt instead of five.

  5. 05 · Ephemeral ML Kitnlp/EphemeralMLKitEngine.kt

    On-device Smart Reply with a 2.5 s timeout; the client is closed in a finally block so it never lingers in RAM.

  6. 06 · Multilingual fallbacknlp/FallbackReplyEngine.kt

    When ML Kit is empty: user pills → late-night chrono bias → script detection → keyword match → English.

  7. 07 · Context enhancercontext/ContextualReplyEnhancer.kt

    Car Bluetooth injects a driving pill; a busy calendar slot injects “in a meeting until 3:30 PM”, localized.

  8. 08 · Silent publish + dispatchpublisher/NotificationPublisher.kt

    An IMPORTANCE_LOW companion (no sound, no vibration, no wake) mirrors to the watch; taps route through ActionBroadcastReceiver.

The zero-cloud contract

The production manifest does not request android.permission.INTERNET. That is not a policy promise you have to trust — it is a build-time fact the OS enforces. The process is physically incapable of opening a socket.

  • No telemetry, no crash reporting, no remote feature flags
  • ML Kit models and notification bundles are disposed right after rendering
  • allowBackup="false" + a data_extraction_rules.xml that excludes every preference file
  • Play Console Data Safety: no data collected, no data shared

How the pills reach your watch

Wear OS

Pixel Watch, Galaxy Watch. Notification actions mirror natively, so the pills render as inline replies; the Play Services data layer can also push a compact JSON payload to a Wear Compose companion.

Full native · direct reply

Zepp OS (Amazfit)

A JavaScript micro-app on the watch talks to the Zepp mobile bridge; the daemon relays reply tokens to the watch screen and the tap comes back over the same channel.

Companion bridge · mirrored actions

Budget RTOS

boAt, Noise, Fire-Boltt. These watches mirror standard Android notification actions, so the injected pills show up as stock quick replies with no companion app at all.

Action mirroring · zero extra app

Questions engineers ask

Is this playground the real engine?

The decision logic is a faithful port: the reply banks, blocklist, regexes and stage order are generated from the Kotlin sources, and playground/test/engine.test.mjs asserts the same expectations as the JUnit suite. What is not here is Google ML Kit — the browser has no on-device model, so the playground always exercises the deterministic fallback path.

Does it need a rooted phone or Xposed?

No. It uses the public NotificationListenerService API and the messaging app's own RemoteInput action, exactly like the system's built-in “Reply” button.

What happens when ML Kit returns nothing?

The fallback engine takes over: your custom pills first, then a late-night bank between 23:00 and 06:59, then script detection (Arabic / Devanagari / Bengali), then Latin keyword matching, then English. You always get pills.

Will OEM battery killers stop it?

Onboarding routes you through ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS and manufacturer autostart screens, and onListenerDisconnected() calls requestRebind() if the ROM kills the service anyway.

Can I ship the engine in my own app?

Yes — :core-engine has no Flutter dependency. Add the AAR and call EngineBootstrap.initialize(this) from your Application.onCreate.

How do I run this page locally?

It is static. cd playground && python3 -m http.server 8080, then open http://localhost:8080. The Tailwind and AOS CDNs are used for styling and scroll animation; assets/styles.css keeps the page readable if a CDN is blocked.
