What is this, actually?

A modern messaging client on Android attaches a direct “inline reply” action to its notifications via Android's RemoteInput API. WristReply AI leverages this exact public architectural bridge. It never scans your screen, never injects accessibility gestures, never launches the messaging application into the foreground, and never dispatches data across an IP network socket. It simply evaluates the incoming text directly on-device and delivers high-precision, localized reply pills straight into the notification.

What it is

A high-efficiency Kotlin NotificationListenerService combined with a sleek Flutter control cockpit for personalizing persona tone, whitelisted applications, profanity shields, and automations. The daemon monitors incoming communication events, confirms reply validity, and publishes a silent companion notification with up to five instant reply pills.

  • Executes autonomously without retaining the Flutter runtime engine in memory (~18 MB RAM, 0% CPU idle)
  • Engine package compiles as an unencumbered standalone .aar library initialized via EngineBootstrap
  • Dynamically inspects and adapts to messaging notifications at runtime without hardcoded application manifests

How it works

An eight-stage deterministic pipeline where each operational phase is bounded to finish under 10 milliseconds: gate inspection → profanity shield → smart token extraction → rapid burst debounce → ephemeral on-device ML Kit → multilingual and intent fallback → contextual enhancement → silent dispatch publishing.

  • Google ML Kit Smart Reply instantiated per-request and strictly released in a finally block to prevent heap retention
  • 2.5-second fail-safe timeout prevents model stalls from delaying notification delivery
  • Thread-safe LRU debounce buffer collapses rapid consecutive messages from one contact into a single prompt

Why it is built this way

Smartwatch interactions demand instantaneous responsiveness and total confidentiality. Cloud-based LLM APIs introduce 300 to 1200 milliseconds of network round-trip latency and expose intimate conversations to external servers. On-device execution produces replies in sub-20 milliseconds while keeping all message content strictly inside device silicon.

  • Google Play Data Safety certified: absolutely zero user data collected, transmitted, or shared
  • 100% operational in airplane mode, subway transit, remote outdoor locations, and roaming
  • No user accounts, no cloud subscriptions, no telemetry beacons, and zero monthly recurring charges
Under the Hood

The eight-stage pipeline

Every phase of the processing pipeline directly correlates to an existing, tested class within the Android Kotlin engine. When a notification arrives, the pipeline executes sequentially and stops early if any security or content rule triggers.

  1. 01 · Notification gateinspector/NotificationGate.kt

    Filters out ongoing playback controls, call statuses, group summaries, blank payloads, and WristReply companion notifications before dedicating any NLP compute resources.

  2. 02 · LPTE profanity shieldfilters/ProfanityGuardEngine.kt

    Scans incoming text against a normalized dictionary of 68 cross-lingual abusive and fraudulent tokens, plus user-defined blocklists, guaranteeing inappropriate messages never receive cheerful auto-replies.

  3. 03 · Token extractorfilters/SmartTokenExtractor.kt

    Detects one-time passcodes (OTP) and transaction reference numbers across global payment gateways (Stripe, UPI, Pix, bKash, Apple Pay, iDEAL) and injects a single-tap copy action into the shade.

  4. 04 · Burst debounceguard/MessageDebounceBuffer.kt

    Prevents notification flooding by aggregating rapid-fire sentence fragments from a single contact within a 1500ms debounce window into a unified prompt before triggering reply models.

  5. 05 · Ephemeral ML Kitnlp/EphemeralMLKitEngine.kt

    Invokes Google ML Kit Smart Reply on local device silicon with an explicit 2.5-second timeout, completely releasing and closing client instances in a finally block to eliminate memory leaks.

  6. 06 · Multilingual fallbacknlp/FallbackReplyEngine.kt

    When ML Kit returns empty suggestions (or for non-English texts), deterministic heuristics engage: custom persona pills → chrono sleep window → script detection → intent heuristics → English default.

  7. 07 · Context enhancercontext/ContextualReplyEnhancer.kt

    Inspects Bluetooth car audio status to inject driving pills, queries calendar providers for meeting status to append localized busy replies, and appends localized location pills when queried.

  8. 08 · Silent publish + dispatchpublisher/NotificationPublisher.kt

    Publishes a silent IMPORTANCE_LOW companion notification that mirrors seamlessly to smartwatches, wiring taps through ActionBroadcastReceiver directly to the messaging client.

Strict Hardware Security

The zero-cloud contract

The application manifest in production code contains no entry for android.permission.INTERNET. This is not merely a privacy policy statement or a corporate promise — it is an operating system enforced security constraint. The Linux kernel running the Android OS sandbox physically prevents the daemon process from opening any network sockets.

  • Zero crash-reporting SDKs, zero third-party analytics trackers, and zero remote feature flag frameworks
  • On-device ML Kit models and notification text bundles are completely deallocated immediately following pill generation
  • Configured with allowBackup="false" alongside custom data_extraction_rules.xml excluding all preference storage
  • Complies with Google Play Data Safety requirements: No data collected, no data stored, no data shared

Engine Details

Questions engineers ask

Common technical inquiries regarding offline execution, battery performance, and platform hooks.

Is this playground the real engine?

The decision logic is a 1:1 port: the reply banks, blocklist, regexes, and stage order are faithfully aligned with the Kotlin sources, and playground/test/engine.test.mjs asserts the exact expectations as the Android JUnit suite. What is not present in the browser is Google ML Kit — because web browsers do not ship with Google Play Services on-device models, the playground exercises the deterministic fallback and intent heuristics paths.

Does it need a rooted phone or Xposed framework?

No. WristReply relies exclusively on the standard Android public NotificationListenerService API and the messaging application's own declared RemoteInput action, identically to how Android Auto and Wear OS trigger inline replies.

What happens when ML Kit returns no suggestions?

The multi-tier fallback engine activates deterministically: custom persona overrides first, then late-night chrono sleep bias between 23:00 and 06:59, then non-Latin script detection (Arabic / Devanagari / Bengali), then conversational intent heuristics, then Latin keyword matching, and finally the English default bank. You will always receive instant, meaningful pills.

Will OEM aggressive battery killers terminate the daemon?

The onboarding flow guides users through ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS and device-specific autostart configuration settings. Furthermore, onListenerDisconnected() automatically triggers requestRebind() to re-establish service connection if terminated by the operating system.

Can I incorporate the core engine into my own Android app?

Yes. The :core-engine module contains zero Flutter dependencies and is published as a standalone AAR. Simply add the dependency and invoke EngineBootstrap.initialize(this) from your Application.onCreate.

How do I execute this website locally?

The playground is static with zero build steps required. Simply serve the directory over HTTP using python -m http.server 8080 or any web server, and navigate to http://localhost:8080. The Tailwind and AOS CDNs furnish layout utilities and animations, while assets/styles.css provides local fallbacks.
